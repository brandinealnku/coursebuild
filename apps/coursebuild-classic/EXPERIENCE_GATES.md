# CourseBuild Experience Release Gates

RC5 treats design quality as a release criterion, not post-release polish.

## Gate 1 — Behavioral usability

A first-time user should be able to complete the core journey without interface coaching:

1. Open or create a course.
2. Understand current course state and next action.
3. Build or inspect the Blueprint.
4. Identify incomplete or unreviewed work.
5. Review AI-assisted content with explicit user control.
6. Prepare the course for Canvas.
7. Resolve a readiness issue.
8. Preview and publish intentionally.

Measure task completion, errors, hesitation, navigation reversals, time on task, and confidence.

## Gate 2 — Perceptual quality

The first view should communicate modern, coherent, trustworthy professional software before the user understands the implementation.

Review hierarchy, typography, spacing, density, visual consistency, state clarity, empty states, loading states, and mobile composition.

## Gate 3 — Emotional response

After completing the workflow, assess whether users would choose CourseBuild again over their prior process. Capture spontaneous language, but do not substitute stated preference for observed task behavior.

## RC5 design rules

- The course is the primary object; Blueprint is its spatial representation.
- Important choices appear before secondary complexity.
- One screen should have one obvious purpose and one obvious next action.
- AI suggests; the instructor decides, edits, approves, and can recover.
- Save, approval, Canvas impact, processing, and reversibility must be visible states.
- Mobile is designed around review, approval, status, correction, and publishing—not desktop compression.
- New features do not outrank unresolved experience debt.
